# 采集、配置和存储

本文描述本项目的实现行为；不把历史样本观察当作其他产品的正式接口契约。

## 模块与数据流

| 模块 | 职责 |
|---|---|
| `FrontmostApplication`、`AXTreeReader`、`InputTap` | 读取前台应用、辅助功能树、键鼠事件 |
| `CollectionSession`、`TextInputTracker` | 编排采样、应用策略、归属文本变化 |
| `UIElementRenderTree`、`UIElementRenderDifference` | 渲染界面树和差分，超预算时回退整树 |
| `SegmentWriter`、`SegmentPruner` | 保存事件、封口元数据、清理旧段 |
| `CollectorProcessLease`、`CollectorSupervisor` | 实例锁、进程身份校验、崩溃重启 |
| `MemoryGenerator`、`NarrativeGenerator` | 生成记忆和时间线叙述；可选调用模型 |

事件类型与编码以 [EventStreamModels.swift](../Sources/ComputerHistoryCore/EventStreamModels.swift) 的 `EventStreamEventKind`、`EventStreamRecord` 和 `EventStreamJSON` 为准。类型可以被解析，不代表采集入口会产生所有事件类型。

## 采集行为与局限

命令行入口每秒检查前台应用与聚焦文本；完整 AX 树在后台读取，完成后在采集线程应用快照，并按完成时刻记录。若上一帧尚未完成，不会并行启动另一帧；应用、窗口或网址切换，以及暂停、配置更新、离开电脑或停止会使过期快照失效。键鼠事件使用系统的只读监听模式，采集处理不拦截输入事件。同步窗口与焦点文本查询仍在采集线程执行，目标应用无响应也可能延迟后续快照。鼠标与快捷键事件通过系统事件监听取得。点击保留鼠标修饰键，目标按鼠标坐标命中；无法确认时不填写目标。快捷键记录修饰键与物理键位名称，Shift/Option 加普通字符仍交给文本跟踪器；无修饰键的 Return/Enter 记录为按键事件，它不直接表示消息发送或文档保存成功。拖动与选择变化尚未连接到完整动作采集入口。

AX 节点身份使用 `CFHash` 加同哈希出现序号。哈希碰撞或碰撞节点顺序变化可能影响匹配，不能保证跨帧完全稳定。新采集的差分省略未变化的节点文本；应用、窗口、文档地址、暂停恢复和段边界会建立完整基线。界面内容变化只写入对应的窗口事件，点击与快捷键不重复携带同一帧。差分预算由 `UIElementRenderDifference.defaultLineBudget` 定义。

快照与文字识别仅在成功写入后确认去重状态。写入失败会清除界面差分基线，恢复后的首帧保存完整界面；失败的输入批次等待重试，期间不消费新的文本观察，暂停及配置变化会丢弃该批缓冲。写入失败和恢复会记入日志。

文本来自聚焦编辑控件的值变化，不是逐键重建。跟踪器按完整 Unicode 字符维护新增编辑区域；落盘前的删除、纠错和替换会更新该区域，不同位置的独立编辑分别保存。含 NUL 的缓冲和明确非编辑控件被排除；终端和部分应用可能缺少有效聚焦元素。应用、窗口号、文档地址或控件身份变化会重建基线，窗口标题变化不会。

键鼠监听只提供附近发生交互的时间信号，不保存普通按键的原始键码。`keyboard.textEvidence` 的 `edited_value` 表示控件变化附近有编辑活动，`uncertain_value_change` 表示无法归因；两者都不证明文本已发送，前者也不证明逐字键入或输入法组合已完成。旧记录缺字段时按未知解读。明确 placeholder 不作为输入；真正编辑了相同短句时仍保留。应用把提示塞进 value、又缺少可区分属性时，只能降低归因强度。

当前公开 AX 读取没有提供通用的输入法组合状态，保持未知。轮询之间出现又消失的文字可能遗漏；已经落盘的拼音不会被原地改写。后续编辑覆盖了已记录区域时，`keyboard.textReplaces` 保存被覆盖事件的 `段ID#事件ID` 来源，派生摘要会标明旧片段已被部分或全部替换。

Chrome 在新进程开始采样时会重新建立辅助功能连接；读取应用的 `AXRole` 后，请求 `AXEnhancedUserInterface` 启用 Chromium 的完整正文树，并尝试 Electron 的 `AXManualAccessibility`。应用尚未准备好时继续重试，运行中定期检查连接；这些请求在观测策略允许后执行。应用仍可能不提供正文，不能保证所有应用或版本可读。

在 macOS 14 或更高版本上，`windowTextApplications` 中的前台应用没有可读的辅助功能正文时，可用 ScreenCaptureKit 捕获该应用的单个窗口，并由系统 Vision 执行 OCR（光学字符识别）。默认不启用；在采集设置的应用列表中添加并勾选，取消勾选后保留条目，保存后自动生效。工具栏和地址栏不作为正文阻止识别。需屏幕录制权限，缺少权限时在 `collector.log` 报错，不自动弹出授权或退回整屏截图。采集前应用观测策略，仅处理当前获得焦点的应用；每次识别结束后至少间隔三十秒再读取，不处理后台缩略窗口。截图只在内存中使用，不保存图像；识别文本可能有错字，按界面内容保存，不当作用户输入或播放结果。该功能会增加本地计算开销。

窗口文字事件仍使用 `window.changed`，`ax.source: "window_ocr"` 标明来源，原有辅助功能事件省略此字段。暂停、应用或窗口切换、锁屏和停止会作废尚未返回的识别结果；重复正文不反复写入。macOS 13 继续使用辅助功能采集，不提供这一窗口识别路径。

暂停会丢弃尚未提交的文本缓冲并清除差分基线。恢复后的首次文本采样仅建立基线；界面树仍可能包含暂停期间写入且仍可见的内容。暂停不是内容擦除或历史脱敏功能。

前台应用为系统登录界面（`com.apple.loginwindow`）时，采集器封口此前的事件段，停止读取界面、聚焦文本和记录键鼠操作。前台重新出现其他应用后恢复采集并建立新基线。离开起止时间保存在数据目录的 `away.json`，满一分钟的时段在时间线合并为一条“离开电脑”，更短的切换不单列条目，不为离开时段调用模型；前台应用暂时不可用时不会据此判定已经返回。锁屏原因基于登录界面的应用身份，不以普通窗口标题判断。采集器还读取系统会话最近键鼠输入的时间，覆盖普通按键、鼠标移动、滚轮和拖动；连续无输入达到 `AwayPeriods.idleThreshold` 后，暂停内容采样并记录“用户离开电脑 / 长时间无操作，未锁屏”。该时段从达到阈值后的首次采样开始，不回填此前时间；输入恢复后重新建立基线，首次点击或快捷键仍正常记录。锁屏优先，原因切换分开保存。手动暂停和正常停止会结束无操作时段，不把暂停或停机间隔当作已观测的空闲。系统空闲表示无键鼠输入，不证明用户物理离席；旧记录没有系统空闲证据时，不从缺少语义事件追认离开。`away.json` 新记录保存原因，旧记录缺少原因时沿用锁屏解释。

`FrontmostApplication.secureInputState()` 返回未知；本实现未检测安全输入模式。域名规则依赖窗口实际提供的 URL（统一资源定位符），读不到地址时不能据此识别敏感网站或隐私浏览。

输入监听状态与权限预检分开报告：`--check` 查看授权，`--status` 和菜单栏“运行状态”查看对应进程的监听状态。系统事件回调只排队输入，辅助功能读取和写盘在回调返回后处理；监听失效时恢复或重建，失败重试间隔由 `InputTap.ensureActive` 维护，后台不主动请求权限。

滚动作为 `mouse.scroll` 记录，按应用、窗口和网址节流；惯性尾段和纯指针移动不单独作为浏览证据。记录数量是采样证据条数，不是手势次数。滚动不作为文本编辑归因。输入法公开组合状态时，未上屏尾部保留在缓冲中，封段不能将它当作最终文字；不支持组合状态的应用仍只能依据实际读到的控件值及后续替换记录判断，不猜测英文是否为拼音。

“无明显活动”要求未记录到点击、滚动、翻页、提交或确证编辑，且该段输入监听有可用记录；短段也使用同一交互规则。界面自动变化、静态正文及 ActivityWatch 的非空闲状态不能单独证明阅读。已知监听失效或旧无活动记录缺少可用性信息时显示“活动证据不足”，不把采集缺失写成用户无操作。已有活动正文不因升级自动重写。

## ActivityWatch 补充来源

在“设置 → 总结提示词与配置 → 采集 → ActivityWatch”启用后，采集器每十五秒只读访问本机 `http://127.0.0.1:5600/api/0/`，读取服务器对应主机的 `currentwindow` 与 `afkstatus` 最新各一条记录。不修改 ActivityWatch、不导入启用前的历史，不访问其他主机的数据桶；服务不可用时记录错误并继续原有采集。

只接受与当前前台应用匹配的窗口记录，并沿用应用和网站屏蔽规则。暂停、锁屏及关闭接入会停止读取并丢弃未完成请求。过期记录不采用，观测时间裁剪到本次启用或恢复之后，重复轮询不重复累计区间。

补充记录使用 `window.changed` 和独立的 `activityWatch` 字段，保留窗口／空闲来源桶、事件编号、观测区间及 `afk`／`not-afk` 状态，`ax` 为空。总结材料会注明 ActivityWatch 来源；它提供应用、窗口、网址和空闲信息，不提供网页正文，也不证明用户阅读、编辑或完成了操作。空闲状态与系统锁屏的“离开电脑”分别记录。

## 配置

`<数据目录>/config.json` 缺失时自动创建模板。默认值以 [CollectorConfig.swift](../Sources/ComputerHistoryCore/CollectorConfig.swift) 的初始化器和 [ObservationPolicy.swift](../Sources/ComputerHistoryCore/ObservationPolicy.swift) 的 `conservative` 为准。

| 字段 | 含义 |
|---|---|
| `maxNodesPerSnapshot` | 单帧最大节点数，正整数 |
| `maxLogBytes` | 监督进程日志上限，正整数 |
| `windowTextApplications` | 窗口文字识别列表的应用标识数组，默认空；例如 `["com.netease.163music"]` |
| `windowTextDisabledApplications` | 列表中取消勾选的应用标识，默认空；不识别这些应用，但保留界面条目 |
| `activityWatchEnabled` | 是否读取本机 ActivityWatch 的当前窗口与空闲记录，默认 `false` |
| `retention.maxTotalBytes` | 可识别段的总量目标；0 禁用容量清理 |
| `retention.maxAgeDays` | 按目录时间戳判断的保留天数；0 禁用年龄清理 |
| `retention.unsummarizedMaxAgeDays` | 未生成记忆或模型失败的段允许延长保留的天数；仍受容量目标约束 |
| `policy.defaultApplicationBehavior` | 应用默认行为：`observe` 或 `do_not_observe` |
| `policy.defaultURLBehavior` | 网址默认行为，取值同上；默认拒绝时也拒绝浏览器缺失或无效的地址 |
| `policy.allowlist`、`policy.blocklist` | 应用或域名规则，阻止优先 |
| `policy.forcedBlockedDomains` | 最后执行的域名阻止列表 |

规则形如 `{"scope":"app","bundleID":"com.example.Editor"}` 或 `{"scope":"url","urlDomain":"example.com"}`。应用标识精确匹配，域名匹配自身及子域。

应用默认拒绝时，缺失或空应用标识也会被拒绝。网站默认拒绝时，系统登记为 HTTP/HTTPS 处理程序的浏览器即使没有提供地址也会被拒绝；普通桌面应用没有网址或只有本地文件地址时只按应用规则判断，提供了无效网址时则拒绝。名单不限制不含应用内容的会话开始与结束事件。规则在读取界面与交互目标的控件值之前执行。

缺字段保留默认值；提供非空名单会替换对应默认名单，显式 `"blocklist": []` 会清空默认屏蔽。未知字段、字段类型不符、非法枚举、空规则和带协议或路径的域名规则会被拒绝，并报告字段位置。缺字段兼容不等于容忍错误字段。

文件读取失败、JSON（JavaScript Object Notation）语法损坏、顶层不是对象或字段校验失败时，采集和监督启动失败，保留原文件供修复。运行中修改配置的生效方式见[模型与用量配置](#模型与用量配置)。

`control.json` 保存 `recording`、`summarizing`、`flushRequested`。文件缺失时前两项默认开启；无法读取或解析时暂停两项。记录开关在采样周期读取，总结开关限制新任务排队，已经排队或执行的任务可继续完成。新事件段封口后触发实时队列，定时周期用于补漏和重试；默认优先处理最近的积压段，每个批次仍按时间顺序建立引用。记忆与时间线串行生成，日报／周报和备份在独立的后台队列执行，不阻塞下一段实时总结。`--no-model` 对监督派生的全部生成任务有效。`--memorize-interval 0` 关闭定时生成，但仍允许手动请求。

## 文件与生命周期

```text
<data-root>/
  config.json
  control.json
  model.json             # 可选模型组与主备选择，不含密钥
  timeline-deletions.json # 从时间线删除的总结标识
  summary.json           # 时间线模式与可选的总结提示词覆盖
  requests/*.json        # 逐次请求、用量和单价快照
  collector.lock
  collector.pid
  collector.log
  segments/<时间戳或时间戳_UUID>/
    events.jsonl         # 活动段
    events.jsonl.gz      # 已归档段，与上者择一读取
    metadata.json
  memories/*.md
  narrative.json
  timeline-edits.json    # 时间线标题、内容与任务名称覆盖
  timeline-corrections.json # 活动拆分与同任务／不同任务约束
  input-listening.json   # 带进程身份的运行输入监听状态
  narrative-work/        # 未完成的归属与概览生成缓存
  reports/daily/*.json    # 日报与对应材料
  reports/weekly/*.json   # 周报与对应材料
  reports/work/*.json     # 分批生成的续跑缓存
  exports/               # 可读文本；预览位于 previews/
  backup.json            # 可选的 GitHub 私有备份设置
  backup-status.json     # 最近成功提交与错误
  .github-backup/         # 独立数据仓库的本地副本
```

JSONL（逐行 JSON）事件逐条追加。新写入的事件、段元数据、运行日志、模型请求及派生记录中的时间字段跟随系统当前时区，并保留 RFC3339 偏移，例如 `2026-10-20T20:00:00+08:00`；旧的 UTC（协调世界时）字符串与旧版数值日期继续可读，不重写历史数据。段目录名仍使用 UTC 作为稳定标识，保持已有引用和清理规则。时间段按绝对时间边界对齐；时长由 `SegmentClock.durationSeconds` 定义。轮转在写入新事件时触发，静默期和暂停期间不会仅因时钟到点就封口。事件编号在同一采集会话内连续，重启重新开始。

同一时间窗重启使用新的 UUID（随机唯一标识）目录，避免覆盖旧数据。元数据在封口时写入；新版本额外保存首条事件时间用于排序。采集启动持有实例锁后，为旧的未封口段补写恢复元数据，不改写原始事件；无法解码的半行不计入恢复事件数，恢复错误写入日志。写入失败会记录错误；停止时封口失败使采集器返回 74，监督进程也退出并保留失败结果，不自动重启。`--stop` 只能确认进程已经退出，封口结果需查看日志。存储并非事务日志系统。

`collector.lock` 使用 `flock`（文件独占锁）阻止同目录多个采集器；身份文件记录 PID（进程号）、启动时间和可执行路径。`--stop` 校验身份后发送停止信号。重复采集器返回 73，监督收到该退出码后退出；停止封口失败返回 74，同样结束监督；其他异常退出按重试间隔重新启动。

监督模式支持脱离终端会话运行。macOS 授权结果受签名、启动来源和系统版本影响；重新构建后可能需要重新授权。项目不保证某一种启动来源一定获得权限，也不自动配置采集器登录启动。

## 清理与日志

`memorize` 在生成前用系统 gzip 流式压缩已封口段，成功写出归档后才删除未压缩原文。采集器不在采样线程压缩。生成、排序和统计同时支持已有 JSONL 与压缩段；读取位置以实际目录为准。

段清理在启动和事件触发的轮转时执行。保护当前段；独立调用清理器时保护排序最新的一段。不能识别时间戳的目录不删除，也不计入可识别段容量。保护段本身可能超过容量目标。

同窗目录按首条完整事件时间排序，时间相同按目录名定序。缺失、损坏、过大或越界的首行退回段起点；这只提供确定性顺序，不能恢复全部历史创建顺序。

年龄清理对未总结或模型失败段使用延长保留时间；容量不足时先淘汰已有可用记忆的段，再淘汰其余旧段，并记录未完成总结的淘汰数量。记忆的 `generation` 字段区分 `model`、`factual` 和 `failed`；旧记忆仍可读取。

删除失败不会计为成功，也不会扣除其占用。统计不完整时暂停容量清理；能识别的超龄目录仍可能被清理。失败详情写入日志。

监督进程在脱离启动时轮转过大的日志，运行时定期检查并限制日志长度。直接运行 `collect` 没有相同的周期日志上限机制。段保留策略不清理记忆、叙述及其他派生数据，详见[隐私文档](privacy.md)。

## 摘要的含义

十分钟记忆结合编辑片段、控件变化、按时间排列的界面内容、点击目标和快捷键取材，按任务归并跨应用操作。每份记忆保留有界的时序证据及事件引用；编辑归属只约束对应片段，不扩展为整段免责声明。摘要直接描述材料支持的动作和结果，没有结果材料时省略，不强行生成结束状态。

模型输入区分明确交互与界面观测，单独统计鼠标、快捷键／提交与确证编辑。窗口变化、倒计时和后台回复不作为持续使用证据；缺少交互也不能推断离开电脑、看手机或没有阅读。首末记录时间只表示观测范围。

观测跨度达到无操作阈值、且只有界面变化而没有点击、快捷键、有效编辑内容或明确活动状态时，十分钟记忆标记为“无明显活动”，活动整理层沿用这一标题与简短说明，不调用模型强行生成任务。原始窗口观察仍保留在来源详情中。此标记表示缺少可归纳的操作证据，不能解释为已确认离席、玩游戏或看手机；系统输入时钟确认的无操作与锁屏仍使用各自的离开原因。首尾相接的无明显活动片段合成一个时间段，不标注成多项任务。旧记忆缺少 `activity_status` 时沿用原展示，显式重算后按事件证据判定。

时序取材优先覆盖包含正文或明确交互对象的记录，避免重复的窗口、空闲元数据挤掉正文；没有正文时才用元数据描述观测范围。界面节点只在选入材料后去重，后续快照仍可补入此前未选中的节点。

总结优先概括交流、阅读和写作内容，省略光标移动、普通快捷键、输入提示和通用完成反馈。取材排除仅含节点编号、控件类型或内部菜单标识的结构，不把节点编号当成窗口数量；只有应用或空窗口时说明未读取到有效正文，不据此推断播放、阅读等行为。长文本保留有界的较完整片段，时序证据用于识别纠错、重命名和导出；相似文件名本身不证明它们是同一文件。

六小时汇总仅保留手动命令与已有记录读取，使用十分钟记忆中的活动正文。时间线模式保存在 `summary.json` 的 `timelineMode`：`fixed10min` 每份十分钟记忆独立生成活动内容；`continuous` 由模型判断相邻任务的连续性，缺省及旧配置保持此模式。同一时间窗重启产生的多份来源各自保留。

顶层时间线由 `TimelineLayout.cards` 确定性排布：时间点唯一，从下往上严格递增，区间不交叉。同刻或相交的活动折叠到一个时间容器，保留各项原内容与时间范围，标题取最早开始的活动并标明活动数量。首尾相接的区间可以分开；链式相交形成同一容器，避免嵌套区间穿插。展开后查看各活动，复制容器会包含全部子活动；删除容器会逐项送入回收站，离开记录不删除。此规则适用于两种模式，不改写已有记忆和模型缓存。

连续模式从十分钟活动正文提取活动片段，先由模型确定分组，再逐组读取对应原文生成概览。分组必须完整、唯一地认领片段，概览不能改变分组。不同目标、聊天、阅读、休闲均独立保留，不按重要性隐藏。应用切换不等于任务切换，同一应用、网站或仓库也不单独证明同一任务。

每批最多提供四份相邻来源，只有相邻、目标一致且未被独立活动打断的片段才可续接。A→B→A 保留三次出现，前后A可关联同一任务；自动关联比较同日本地日期最近的候选任务，范围由 `NarrativeGenerator.generate` 维护。离开与采集断裂阻断时间块续接，但不阻止同任务关联。片段编号表示原文位置，不代表精确操作顺序；显示来源时段，不推算投入时长。续接重新读取原活动正文，标题保留稳定目标。

归属和概览请求分别记录为“活动归属”和“活动整理”，共用模型、预算与降级设置，串行执行。失败时在 `narrative-work` 保留已完成阶段供续跑；只在整批概览完成后替换正式结果，显式重算仍以一天为保存单位。

展开概要中的“原活动内容”保留所选片段正文；历史 `~` 分类不再弱化展示，旧兜底标题从来源活动恢复，重新生成后使用具体标题。自动标题不保留末尾中文句号，正文与手动标题不变。固定十分钟模式继续每份来源独立生成，展示完整活动内容；来源时段冲突时，仍遵守时间容器的折叠规则。


增量生成只处理未覆盖或内容已修订的来源，没有新增时不请求模型。普通增量每批成功后保存；失败保留可用缓存。显式重算以一天为保存单位，某天失败或取消时保留该天原有摘要，已完成的其他天保留。旧叙述缺少来源修订信息时会补做一次；模型输出仍是派生内容。

拆分后的临时条目和未归纳的记忆优先展示来源的活动正文，不用事件数量与应用列表替代已有正文；已完成的活动摘要保持不变。

时间线优先用段元数据里的首条事件时间与封口时间显示记录范围；缺少首条事件时间时，使用分段时间，并在已知的返回边界内校正。显示范围不是精确的操作时长。离开条目显示系统记录的原因，正在持续的时段也会展示；不据此推断睡觉、通勤等活动。

没有模型配置或显式使用 `--no-model` 时，记忆与叙述可生成事实版本；用户有意生成的事实记忆不会自动变成模型待办。损坏的 `model.json` 或已配置模型缺少必需密钥时，生成任务返回失败，不写入已完成的事实版标记；`--no-model` 仍可离线使用。模型请求失败或输出截断会标记失败，后续周期重试。显式 `--overwrite` 可重做已有记忆。

`verify` 检查能由现存段映射到的十分钟记忆引用，不验证所有数据完整性、模型事实正确性或已经清理的原始段。段内首末事件跨度也不是精确活动时长。

## 报告、导出与备份

日报按本地自然日，周报按本地周一至周日划分。报告保存其生成时区。监督进程每轮在十分钟记忆、时间线整理之后补齐已结束时段的报告，每轮上限见 `ReportGenerator.generateMissing`。自动和手动生成都会先补齐报告时段内已封口、缺失或失败的十分钟记忆；已有可用记忆保留，其他时段不重算。记忆生成正忙时等待其完成后继续，补齐失败则保留已有报告并显示具体原因。尚未封口的来源不强行结束，正式报告等待后续周期重试。当天或本周的手动生成显示“截至当前”，时段结束后重新生成正式报告。来源变化会更新报告，旧原始记忆不被改写。

日报取十分钟记忆的活动正文；缺少模型活动正文时使用已有记忆的事实摘录。周报使用完整日报，手动生成周报会先补齐所需日报。报告材料不混入此前记忆、用户特征小节、原始时序证据和本地引用路径。普通报告一次请求生成，超过 `ReportGenerator.materialBatchLimit` 的材料才分批并合并，已完成批次保存后可续跑；模型失败、空输出或截断不替换已有报告。全部模型请求沿用 `model.json`、钥匙串、预算及请求台账。`--no-model` 只生成活动材料版报告。

菜单栏“日报、周报与导出”提供报告类型和日期选择、生成／重新生成、复制报告、复制给 AI 的材料及 Markdown／TXT 导出。复制材料和导出不调用模型，也不受时间线分页条数限制。TXT 导出移除标题标记、粗体和反引号，保留完整文字。

```bash
computer-history report --day 2026-10-18
computer-history report --kind weekly --day 2026-10-18
computer-history report                         # 补齐已结束的日报／周报
computer-history export --day 2026-10-18 --copy
computer-history export --day 2026-10-18 --material --format txt --file material.txt
```

GitHub 私有备份默认关闭。先使用 GitHub CLI（`gh`）登录并创建独立私有数据仓库，再在“设置 → 总结提示词与配置 → 备份”填写 `owner/repository`、开启并保存；设置区的“GitHub 私有备份”开关直接启停已保存的配置。`backup.json` 保存 `repository` 与 `enabled`，下一次任务读取；关闭后不会启动新的上传，已经开始的任务可能继续完成。不会创建仓库或改变仓库可见性。

```bash
gh auth login
gh repo create <owner>/<data-repository> --private
computer-history backup --repository <owner>/<data-repository>  # 配置并启用，不立即上传
computer-history backup                                       # 手动上传
computer-history backup --disable                             # 关闭自动和手动上传
```

启用后监督进程每天首次备份成功后跳过当天后续自动任务；失败后下一周期重试。手动“立即备份”读取已保存的设置。上传前检查仓库为私有，使用独立本地副本，只提交 `archive/activities`、`archive/daily`、`archive/weekly` 下的 Markdown。预览、原始事件、完整记忆文件、配置、请求台账、日志和分批缓存不上传。备份更新不传播本地清理造成的删除，不强制推送；远端分叉会报错。成功状态需在推送后核对远端提交。`backup-status.json` 和备份设置页显示最近成功时间或错误。导出目录和备份不受事件段清理策略管理。

## 菜单栏读取

菜单栏在串行后台加载器中读取统计和时间线。已封口段优先使用 `metadata.json` 的事件计数；缺少或无法解析时流式计行并缓存，未封口段只计新增字节，包含尚未以换行结束的非空尾行。截断、替换和删除会使相应计数更新；无法完整读取时界面标注统计下界。

记忆索引按文件大小、修改时间和文件身份复用解析结果；列表快照只持有展示字段，详情按需后台读取。刷新请求会合并，文件读取与跨进程窗口查询不在主线程执行。菜单栏也支持 `--out <目录>`，独立目录使用独立实例锁；默认目录与 CLI 相同。


### 时间线模式、编辑与复制

在“设置 → 总结提示词与配置 → 时间线”选择模式并保存，然后选择“重算当天总结”“重算所有总结”或“不重算”。重算使用已有十分钟记忆与当前模型，只更新活动整理结果，保留原始事件和十分钟记忆。保存模式本身不会请求模型；“不重算”保留自动摘要缓存，展示仍按所选模式排列。重算过程中可以停止；命令行对应 `narrative --overwrite [--day YYYY-MM-DD] --wait-lock`。添加 `--preview-out <新目录>` 可冻结指定日期的来源并生成独立预览，正式事件、记忆和叙述保持不变；失败后相同目录可续跑。预览不复制模型凭据，请求仍使用原目录的模型、费用台账与预算。

摘要单击复制，双击编辑标题和内容，也可通过展开后的“编辑摘要”或右键菜单进入。时间容器双击展开子活动；未归纳的连续模式来源详情、原始事件、十分钟正文和其他阶段性总结保持只读。“恢复自动摘要”移除覆盖层。手动文本保存在 `timeline-edits.json`，只影响时间线展示和复制，不改写来源记忆、日报、周报或导出材料。连续摘要的覆盖绑定来源片段和修订，不依赖模型生成的条目标识；来源正文修订后不将旧覆盖套到新内容。

展开活动可查看“同一任务的其他时段”并进入各自原内容，也可编辑任务名称。多选后的“归属”菜单支持“关联为同一任务”“标记为不同任务”“按来源片段拆分”和撤销上次归属修改。纠错保存在 `timeline-corrections.json`，优先于自动关系，不改原始证据。来源修订使约束失效时界面提示重新确认；拆分以现有活动片段为单位，不提供没有时间证据的秒级边界编辑。

底栏“多选摘要并复制”进入选择状态，勾选需要的活动后点击“复制所选”，按时间先后复制标题、内容和日期时间；可继续滚动选择更早的条目。未选条目及离开时段不复制。底栏回收站只显示图标，悬停可查看名称；“查看日志”位于顶部默认折叠的“运行状态”中。

### 删除时间线总结

右键总结行选择“删除总结”，或在展开概要后点击“删除总结”。删除后在面板底部的“回收站”查看标题、全文、活动时段、删除时间、应用与来源，并逐条恢复或彻底删除。回收站和恢复后的消息快照保存在 `timeline-deletions.json`，刷新、重启或重新生成后仍保留。旧版只有删除标识的记录会尽可能从现有缓存补齐详情；来源已不存在时标为不可用。

恢复可使用保存的消息快照，不要求生成缓存仍然存在。彻底删除会移除回收站条目和该快照，并保留不含正文的标识防止同一条重新出现；原始活动、来源记忆和独立生成缓存保留，日报与周报的取材范围不变。离开电脑的时间段不提供此操作。


## 模型与用量配置

远端服务默认要求 HTTPS，本机回环地址保留 HTTP。若明确接受局域网明文传输风险，可在模型组中勾选“允许此服务使用明文 HTTP”，或为该组设置 `"allowInsecureHTTP": true`；旧版单模型配置及其 `fallback` 分别支持此字段。缺省为关闭；HTTP 地址被拒绝时不会退回其他地址。模型列表和生成请求使用相同规则，重定向需改为最终接口地址。传输与内容边界见[隐私说明](privacy.md)。

菜单栏“设置 → 总结提示词与配置”可分别编辑十分钟记忆、活动整理、日报和周报的完整系统提示词。“恢复默认”先载入内置提示词，点击“保存”后生效；默认提示词仍由对应生成器维护。自定义提示词需保留内置提示词中的输出格式，以便解析。

连续模式由内置归属提示词返回片段分组及任务关系，概览阶段逐组返回标题与正文；设置中的“活动整理”提示词用于概览写法，程序追加该次需要的输出格式。固定十分钟模式继续使用 `## [S1] 标题`，每份来源独立一条。归属、编号或概览格式无效时返回失败并保留旧结果。来源正文是待整理的数据，不作为指令执行。

覆盖值保存在 `<数据目录>/summary.json` 的 `tenMinutePrompt`、`narrativePrompt`、`dailyPrompt` 和 `weeklyPrompt` 字段；旧的 `sixHourPrompt` 仍供手动六小时汇总使用。省略字段使用内置提示词，保存默认文本时会移除该覆盖值。空白提示词、未知字段、错误类型或损坏的文件会报错，不继续发起对应模型请求。无模型活动整理仍读取时间线模式，不调用模型。

生成任务启动后读取提示词设置，已经执行的任务继续使用其原提示词；修改不追溯重写历史。自定义提示词不会随内置默认更新，恢复默认并保存后才重新跟随内置提示词。活动整理的模式规则随来源材料发送，请求详情中的“系统提示词”和“输入”分别显示该次实际发送的内容。

设置页的“模型”使用统一的模型组表单：每组保存名称、服务地址、模型名称、请求格式、推理强度、超时、单价和独立密钥。新增后可分别选择主模型组与备用模型组，也可关闭备用；编辑组与实际使用组分别选择，未启用的组仍保留配置。主备不能选择同一组，删除正在使用的组前需先更换选择。所有修改点击“保存”后供下一次生成任务读取。密钥使用密码框输入，留空保留已有密钥，按数据目录和组标识保存在 macOS 钥匙串中，不写入 JSON；交换主备时密钥跟随组。

“从服务获取模型”只在点击时读取该组服务的 `GET /models`，携带该组需要的认证，不发送历史活动或提示词。服务返回模型后使用列表选择；不支持接口、读取失败或需要列表以外的模型时可手动填写。若所选模型返回 `effort.supported_levels` 和 `effort.default_level`，界面显示服务提供的强度与默认值；否则仅保留自由输入，不预设各厂商的等级。

“采集”表单可选择记录或排除的应用、网站域名和文字识别应用，并修改保留策略。应用通过选择器添加，无需填写应用标识。运行中的采集器在采样前检查配置变化，应用有效配置时重建文本基线并丢弃旧缓冲；无效配置会报错并继续使用上次有效设置。新保留限制在下次清理时使用，日志容量上限在监督进程下次启动时读取。

各页的“高级选项”保留用默认编辑器打开 `summary.json`、`model.json` 和 `config.json` 的入口，以及重新读取文件的操作；首次使用需先保存设置以创建对应文件。格式见本节与[配置](#配置)。读取配置失败时显示错误，不以默认表单覆盖该文件。

生成任务每次启动时读取数据目录中的 `model.json`。文件存在时优先使用其中设置；不存在时使用 README 中的 DeepSeek 环境变量。错误配置不会切换到其他模型服务。

模型组均使用 OpenAI 兼容的 `/chat/completions`，项目不管理订阅登录、账号池或 provider 转换。使用网关时填写其兼容接口地址与模型名即可。`requestStyle` 为 `standard` 时发送 `max_tokens` 和 `temperature`；为 `reasoning` 时发送 `max_completion_tokens` 并省略采样温度，为思考和正文一起预留输出预算。预算计算见 `DeepSeekClient.completeAttempt`。请求格式仅控制这些参数，不代表开启或关闭推理。`reasoningEffort` 可省略或留空，此时不发送 `reasoning_effort`，使用服务端默认值；填写时原样发送接口支持的强度，不转换厂商命名；`timeoutSeconds` 可设为 1 至 600 秒，限制单次模型尝试的总耗时；网关的保活数据不会延长此上限。

`model.json` 的 `groups` 是同一格式的模型组列表，每组的 `id` 必须唯一且保持稳定，`name` 用于界面展示；其余字段由 `ModelGroup` 定义。`primaryGroupID` 指向主组，`fallbackGroupID` 指向另一个组，省略或设为 `null` 时关闭备用。预算 `dailyBudget`、`monthlyBudget` 位于顶层，以主组单价的币种计费。下例可直接作为配置格式参考：

```json
{
  "groups": [
    {
      "id": "cloud",
      "name": "云端模型",
      "baseURL": "https://api.deepseek.com",
      "model": "deepseek-flash",
      "requiresAPIKey": true,
      "requestStyle": "standard",
      "timeoutSeconds": 60
    },
    {
      "id": "local",
      "name": "本地模型",
      "baseURL": "http://127.0.0.1:11434/v1",
      "model": "computer-history-qwen3.5-4b",
      "requiresAPIKey": false,
      "requestStyle": "standard",
      "timeoutSeconds": 60
    }
  ],
  "primaryGroupID": "cloud",
  "fallbackGroupID": "local"
}
```

旧的单模型加 `fallback` 配置仍可读取；首次在界面保存时转为 `legacy-primary`、`legacy-fallback` 两个组，并沿用旧钥匙串项目，无需重新输入密钥。读取配置本身不会改写文件。主模型失败、超时、响应格式错误、空输出或截断时，才使用同一材料请求一次备用模型；不会持久切换主组。达到预算时停止请求，不通过备用绕过预算。`model-key [--fallback]` 从标准输入保存当前所选组的密钥，不回显内容。组内已存密钥优先，缺失时主组可读取 `DEEPSEEK_API_KEY`、备用组可读取 `COMPUTER_HISTORY_FALLBACK_API_KEY`；无需密钥的组不读取或发送密钥。

后台命令禁用钥匙串验证弹窗，授权不足时返回错误。`model-key --check [--fallback]` 静默检查当前组的密钥是否可读；设置页的“授权 → 恢复密钥访问”可显式请求系统授权，命令行对应 `model-key --authorize [--fallback]`；`--all` 检查所有已保存的模型组。应在系统验证中选择“始终允许”，程序会再用一个后台进程验证权限确已保留。这两个命令均不回显密钥，也不调用模型。

请求台账的 `fallbackOf` 将降级尝试关联到失败的主请求，分别保留实际用量和费用。历史 `comparisonOf` 仍可读取；旧配置中的 `comparison` 不再发起并行请求，保存模型设置时移除。所有尝试均失败时，生成命令返回非零退出码并保留失败事实版，`model-health.json` 保存错误，主面板显示失败入口并发送系统通知；重复故障通知有间隔限制。主模型失败但降级成功时不发送故障通知。

旧格式的 Ollama 单模型配置示例（也可在上面的统一模型组中填写相同字段）；跨机器使用时填写模型机器的可达地址：

```json
{
  "baseURL": "http://127.0.0.1:11434/v1",
  "model": "computer-history-qwen3.5-4b",
  "requiresAPIKey": false,
  "pricing": {
    "currency": "CNY",
    "inputPerMillion": 0,
    "cachedInputPerMillion": 0,
    "outputPerMillion": 0
  }
}
```

在 Ollama 模型机器上用以下 Modelfile 创建指定上下文的模型，然后执行 `ollama create computer-history-qwen3.5-4b -f Modelfile`：

```text
FROM qwen3.5:4b
PARAMETER num_ctx 16384
PARAMETER num_predict 2400
```


`requiresAPIKey: true` 优先读取该数据目录在钥匙串中保存的密钥，没有时读取 `DEEPSEEK_API_KEY`；密钥不写入配置和请求记录。`reasoningEffort` 留空或省略时使用服务端默认值；已有的显式配置（包括 `none`）继续保留。服务需支持 `/chat/completions`、文本消息和该模型的思考参数。

`pricing` 可省略，此时显示费用未知。单价单位为每百万 token，按输入未缓存、输入缓存命中和输出分别计算；思考 token 是输出的子集，不重复计费。零单价表示模型 API 费用为零，不包含设备运行成本。单价由使用者按服务账户配置；记录保存请求时的单价，调整后不会追溯改变旧请求。面板显示估算费用，服务商折扣、时段价格和账单以实际账户为准。

可选的 `dailyBudget`、`monthlyBudget` 与 `pricing.currency` 同币种；已记录的估算费用达到预算后不再发起新请求。已有请求会执行完毕，用量未知的请求无法计入该估算。

每次请求在外发前先保存 `requests/<随机标识>.json`，返回后补写状态、耗时、正文和服务端用量；文件写入失败时不会继续发起未登记的请求。超时或错误未返回用量时保留未知值。请求状态为“已返回”仅表示接口返回正文；具体生成是否可用还由记忆与叙述解析判断。请求正文和元数据保存在同一文件，菜单栏仅缓存列表字段，详情按需读取。

“总结用量与费用”按实际模型请求统计，包含补齐、重试、主模型和备用模型的独立尝试；本地事实归纳、无明显活动判定与时间线折叠不产生模型请求。未知用量或费用不计入相应合计，不能视为零。历史六小时汇总请求保留查询入口。
